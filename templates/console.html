H5 商城接口回归与缺陷单

白话说：这次写的不是商城功能，而是一个「自动检查员」。它按清单逐个调用接口、比对结果， 把不对的地方记成缺陷单，最后出一份能看懂的测试报告。

35 条用例 · 6 张缺陷单 pytest 调度 + requests 发请求 + Allure 结果
被测商城内置在本仓库，缺陷可一键注入 / 一键修复
测试调度员 pytest

负责按清单一条条跑用例、统计通过失败、把失败原因收集起来。相当于「考试监考 + 阅卷」。

发请求的人 requests

用代码模拟手机 App 调接口，带上 token（登录凭证），拿到返回的 JSON 再断言对不对。

报告生成器 Allure

把每条用例的耗时、状态、请求响应证据整理成网页报告。本机无 Java，所以另附一个免安装单页报告。

操作台 先跑一次看 6 个缺陷被抓出来，再点「模拟全部修复」重跑，看 35 条全绿

📄 打开测试报告

回归会重置商城种子数据 → 逐条调用接口 → 生成 allure-results / JUnit XML / 单页报告 / 缺陷单。

一轮回归是怎么走完的 由外向内，六步

  1. 拉起被测服务本地 Django 跑起商城 API，健康接口先探活
  2. 重置种子数据每条用例前清场，避免上一条的订单影响下一条
  3. 登录拿 tokenfixture 统一管登录态，用例里不重复写登录
  4. 逐条断言状态码 / 统一契约 / 业务字段 / 权限 / 耗时
  5. 留证据失败时把请求与响应 JSON 挂到报告附件
  6. 出报告与缺陷单Allure 结果 + 单页 HTML + 6 条规范化缺陷单
